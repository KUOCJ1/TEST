# 改善計畫（2026-11）：三個 Sprint

> 產出方式：2026-11-14 以「Grill me」式提問向產品負責人確認方向，再對照程式現況找證據。
> 這是規劃文件，尚未實作；每個 Sprint 開工前要再確認「待你決定」的項目。

## 0. 提問結果（決策依據）

| 問題 | 回答 | 對規劃的影響 |
|---|---|---|
| 未來 3 個月最重要的生意目標 | 把現有客戶專案交付得更好 | 不做多租戶、不做公開銷售相關功能；一切以森永、韋能這類專案的交付品質為準 |
| 學員拿到報告後的實際狀況 | 看一次就不再回來 | 平台後段（發展目標、學習資源、複測）目前等於沒被用到，是最大的價值缺口 |
| 三件卡住的事（70 題授權、羅盤啟用、政策法務） | 都不急 | 三項都不排入這三個 Sprint，維持現狀 |
| 結案交給客戶的東西 | 直接給平台的班級報告 PDF | 班級報告 PDF 就是對客戶的最終交付物，它的內容決定客戶怎麼看這個專案的價值 |

## 1. 現況證據（程式裡查到的）

1. **班級報告 PDF 沒有課前課後比較。** `components/GroupPrintableReport.jsx` 只有四章：封面、班級整體落點、群體敘事、成員排名。課前課後分析只存在畫面上（`coach/PrePostAnalysis.jsx`），課後問卷彙總（`lib/courseSurvey.js`）與 30／60 天追蹤（`lib/courseFollowUp.js`）也都沒進報告。客戶拿到的 PDF 回答不了「這堂課有沒有效」。
2. **班級報告有「成員排名總覽」一章。** 交給 HR 或老闆的文件裡有個人排名，容易被當成考核依據，與平台「發展用途、不是評定」的定位衝突，也是客訴風險。
3. **回訪機制只有 Email 與站內提醒。** 複測提醒、評語通知走 SMTP（`lib/notifications.js`），未設定就整個停用；沒有推播、沒有 LINE。台灣企業學員幾乎不看工作信箱以外的通知信。
4. **報告頁沒有把人推向「一個行動」。** 發展目標（`routes/goals.js`）功能完整，但學員要自己發現並建立；結果頁資訊量大，沒有收斂成一個承諾。
5. **教練看不到「誰沒動」。** 教練只看得到已分享的目標（`sharedGoals`），沒有班級層級的行動概況；系統也沒有記錄學員是否回訪，所以「看一次就不回來」目前是觀察，沒有數字。

## 2. 三個最重要的改善計畫

| 順序 | 計畫 | 解決什麼 | 為什麼排這個順序 |
|---|---|---|---|
| Sprint 24 | 客戶版成效報告 | 交付物能證明成效 | 直接對應「把專案交付得更好」，而且資料平台裡都有了，只差整合進 PDF，投入小、客戶馬上看得到 |
| Sprint 25 | 報告後的第一個行動 | 學員看一次就不回來 | 先讓學員在離開報告頁前留下一個承諾，後面的提醒才有東西可以提醒 |
| Sprint 26 | 教練的行動儀表板與回訪數據 | 教練不知道誰需要推一把；回訪沒有數字 | 依賴 Sprint 25 產生的行動資料；做完之後下一輪決策才有數據，不必再靠印象 |

三者連成一條線：學員留下行動（25）→ 教練看得到並推動（26）→ 成果寫進給客戶的報告（24）。先做 24 是因為它不依賴另外兩個，而且最快讓客戶有感。

## Sprint 24　客戶版成效報告（✅ 已實作 2026-11-14：24.1–24.5；預設客戶版不列姓名、建議下一步不連課程名稱，可再改）

**目標**：班級報告 PDF 成為一份能交給 HR／老闆、回答「這個專案帶來什麼改變」的文件。

### 工作項目與驗收條件

| # | 項目 | 驗收條件 |
|---|---|---|
| 24.1 | 新增「課前課後比較」章 | 班級同時有課前與課後自評時，PDF 多一章：總分與各構面的前後平均、變化量、進步最多／最少的構面；只比「兩次都有作答的人」，並標示人數。沒有課後資料時不出現該章，也不報錯 |
| 24.2 | 新增「給管理者的一頁摘要」 | 第二頁：參與率、整體落點、三個優勢、三個優先發展構面、建議的下一步（沿用 `dimensionInsights.js` 與群體敘事，不新寫計分）。一頁內排完 |
| 24.3 | 課後問卷與追蹤彙總進報告 | 班級有附加課後問卷時，多一章：滿意度、能力自評前後、30／60 天追蹤完成率。沿用伺服器現有彙總與「少於 3 人不顯示」規則，個人明細不進報告 |
| 24.4 | 成員排名改為可選 | 產出報告時可選「客戶版（不含個人排名）」或「教練版（含排名）」，預設客戶版；檔名帶版本，避免拿錯 |
| 24.5 | 手機閱讀版同步 | `GroupReadView` 加上相同章節；A4 與閱讀版的章節一致性有測試檢查 |

### 已知取捨

- 前後比較只呈現平均與變化量，不做統計顯著性檢定：班級通常 10–30 人，檢定結果容易被誤讀。報告上要寫明「描述性比較」。
- 不做客戶品牌客製（Logo、配色），先確認內容有用再說。

### 待你決定

1. 客戶版是否完全不出現個人姓名，還是保留「已完成名單」？
2. 一頁摘要的「建議下一步」要不要連到你實際有開的課程名稱？

## Sprint 25　報告後的第一個行動（✅ 已實作 2026-11-14：25.1、25.2、25.3、25.5；25.4 推播未做，待決定）

**目標**：學員離開報告頁之前，留下一個具體承諾；之後有合適的管道提醒他回來。

### 工作項目與驗收條件

| # | 項目 | 驗收條件 |
|---|---|---|
| 25.1 | 結果頁的「選一件事」 | 結果頁最上方（分數區塊之後）出現一張卡：依最弱構面給 2–3 個起手行動（沿用 `goal-starters.js`），點一下就建立發展目標並設定第一次檢視日。已有進行中目標的人看到的是「回報進度」 |
| 25.2 | 一鍵回報 | 提醒信與站內提醒的連結直接開到該目標的回報畫面，三個選項（做了／做了一部分／還沒）加一句選填心得，10 秒內完成；不需要再找頁面 |
| 25.3 | 提醒節奏 | 建立目標後第 3、10、24 天各提醒一次，回報過就跳過該次；可在個人設定關閉（沿用現有通知偏好） |
| 25.4 | PWA 推播（視決定） | 已安裝到主畫面且同意通知的學員，提醒改走推播；未同意者維持 Email。iOS 需 16.4 以上且已加入主畫面 |
| 25.5 | 政策文字同步 | 新增通知管道或資料用途時，更新隱私權政策與 `POLICY_VERSION`（前後端一致，有測試） |

### 已知取捨

- LINE 通知觸及率最高，但需要 LINE 官方帳號、Messaging API 與學員綁定流程，工作量約等於一整個 Sprint。本輪先做推播與 Email，LINE 留待 Sprint 26 的回訪數據出來後再決定。
- 不做 AI 個人化建議：成本與內容審核方式未定（Backlog 既有項目）。

### 待你決定

1. 推播要不要做？做的話要改隱私權政策，既有學員會再看到一次同意畫面。
2. 正式站的 SMTP 目前是否已設定？沒設定的話，這個 Sprint 的提醒全部不會發出，要先處理。

## Sprint 26　教練行動儀表板與回訪數據

**目標**：教練一眼看出誰需要推一把；平台開始有「學員有沒有回來」的數字。

### 工作項目與驗收條件

| # | 項目 | 驗收條件 |
|---|---|---|
| 26.1 | 班級行動概況 | 教練班級總覽多一區：已設定目標人數、近 14 天有回報人數、完全沒動的人數。只顯示彙總；個人層級只列出「同意分享給教練」的目標（沿用 `sharedGoalForCoach`，不含筆記） |
| 26.2 | 設定目標時預設詢問是否分享 | 25.1 建立目標時多一個選項「讓教練看到這個目標」，預設不勾；說明教練看得到什麼、看不到什麼 |
| 26.3 | 教練一鍵提醒未行動者 | 對「還沒設定目標」的成員寄提醒（沿用班級提醒信與 1 小時冷卻）；教練看不到是哪幾位沒有分享，只對全體未設定者發送 |
| 26.4 | 回訪紀錄 | 伺服器記錄每位使用者每天是否有登入活動（只記日期，不記頁面與行為）；管理後台顯示各班「報告後 7／30 天內回訪比例」，少於 3 人不顯示 |
| 26.5 | 行動成果進客戶報告 | Sprint 24 的客戶版報告加一行：設定目標比例、有持續回報的比例（彙總） |

### 已知取捨

- 回訪紀錄刻意只記「哪一天有來」，不做頁面層級的行為追蹤：夠回答問題，也不會變成監控學員的工具。
- 新增蒐集「活動日期」屬於資料處理方式的改變，政策文字要同步更新。

### 待你決定

1. 教練能不能看到「誰沒有設定目標」的名單？目前規劃是不能（只有人數），保護學員；但這會降低教練追人的效率。

## 3. 刻意不排進這三個 Sprint 的項目

| 項目 | 原因 |
|---|---|
| 70 題 360° 授權與歸屬、領導力羅盤啟用、隱私權政策法務審閱 | 產品負責人表示目前不急 |
| 企業多租戶、公開銷售相關 | 與「把現有專案交付好」無關 |
| LINE 通知、AI 個人化學習建議 | 等 Sprint 26 的回訪數據，再判斷值不值得投入 |
| 學員自助匯出／刪除資料 | 目前由管理者人工處理即可；客戶數增加後再做 |

## 4. 風險與反向觀點

1. **學員不回來，可能不是平台的問題。** 如果客戶的專案設計裡沒有「課後要回來做什麼」，再多提醒也只是打擾。Sprint 25 開工前，建議先在一個實際班級用人工方式（教練在課堂上帶大家設定一個目標）試一次，確認學員願意做，再把它做成功能。
2. **成效報告可能呈現「沒有進步」。** 加入課前課後比較後，報告會如實顯示沒進步或退步的構面。這對客戶是誠實的，但對專案續約可能不利。要先想好：退步時報告怎麼寫、你怎麼跟客戶解釋（例如自評標準隨認知提高而變嚴）。
