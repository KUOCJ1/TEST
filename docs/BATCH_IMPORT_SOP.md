# 批次上傳作答資料 SOP（線外收集的資料匯進平台）

適用：問卷在線外收集（紙本、Google 表單、Excel），要把每個人、每一題的分數匯進平台，直接用平台的分析與報告。
對象：管理員（批次上傳只有管理員能做）。系統版本：Sprint 21（2026-11-02）起。

> 「解答」指**每題的作答分數（1–5）**。這些評量都是李克特量表，沒有標準答案；反向題由系統自動反轉計分，**不要自己換算**。

## 流程總覽（順序不能亂）

```
A. 決定評量與專案  →  B. 整理資料  →  C. 上傳前檢查  →  D. 上傳  →  E. 建班與加成員  →  F. 檢查與產出報告
                                                              ↑ 出錯：G. 移除已匯入的作答 → 修正 → 回到 D
```

## A. 決定評量與專案（一次性）

1. 確認這批資料是**哪一份評量**的（題數、題目要和評量一致）。不確定時先看客戶的題目清單，對照管理後台「題庫內容」或 `docs/` 裡的規格。**題目對不上就不要硬傳**（例如 70 題的資料不能傳到 90 題的 L9D）。
2. 客戶專案：到 **管理後台 →「專案範本」→ 新增**，建立這個客戶的範本（名稱、客戶名稱、評量、是否附加課後問卷、是否專屬班級）。之後開班選範本，評量就鎖定，不會選錯。
3. 如果是全新的題目（平台沒有這份評量）：先請開發新增題庫，再回來匯入。

## B. 整理資料（線外，在 Excel 或試算表）

1. 到 **管理後台 →「批次上傳」→ 步驟 1，選好評量 → 按「下載範本 CSV」**。範本的欄位就是這份評量要的欄位，**照它填，欄位名稱不要改**。
2. 一列 ＝ 「一位評分者對一位受評者」的一份作答。欄位：

| 欄位 | 說明 |
|---|---|
| `ratee_email` | 受評者（被評的人）的 Email，必填 |
| `ratee_name` | 受評者姓名 |
| `rater_type` | 英文：`self`（自評）／`manager`（主管）／`peer`（同儕）／`subordinate`（部屬） |
| `rater_email` | 評分者 Email；`self` 這列留空，其他類型必填 |
| `rater_name` | 評分者姓名；`self` 這列留空 |
| `phase`（選填） | 階段：`pre`（課前／前測）或 `post`（課後／後測），也可填「課前」「課後」；留空＝不標記（分析時視為前測） |
| 題目欄位（`l1`…） | 每題的分數，1–5 的整數 |

3. **只做自評（沒有他評）**的評量（例如 AI 評測）：每人一列，`rater_type` 填 `self`，`rater_email` 留空。
4. **360°**：每位受評者要有一列 `self`，加上各評分者各一列。
5. **Email 的處理（重要）**：
   - 同一個人，在所有列裡要用**同一個 Email**（系統用 Email 辨識是不是同一個人）。
   - 沒有真實 Email 時，可以用占位 Email（例如 `客戶-01@placeholder.invalid`）。這種帳號**不能登入、收不到信**，只能由管理員在後台看報告。**之後要改成真的 Email 比較麻煩，所以能拿到真的就先拿。**
6. Google 表單匯出的資料：欄位標題通常是整句題目，要改成題號欄位（`l1`、`l2`…），並補上 `ratee_email`、`rater_type` 等欄位；「時間戳記」「分數」這類欄位刪掉。
7. 存成 **CSV（UTF-8）或 .xlsx**，單次最多 2,000 列。

## C. 上傳前檢查（對照清單，五分鐘）

- [ ] 評量選對（題數、題號與檔案一致）。
- [ ] **每一列的每一題都有分數**，沒有空白（空白的列預設不會匯入）。
- [ ] 分數都是 1–5 的整數（不是「同意」「N/A」，也不是 0）。
- [ ] `rater_type` 是英文小寫的四種之一。
- [ ] 需要前後測比較時，`phase` 欄只有 `pre`／`post`（或課前／課後）或空白。
- [ ] 同一個人的 Email 前後一致，姓名拼法一致。
- [ ] 360°：每位受評者都有 `self` 列；不要出現沒有受評者的評分。
- [ ] 沒有重複的列。同一位評分者對同一位受評者重複填兩次時，資料會兩筆都存入，只是報告與分析取最新一筆；重複的列請先清掉。
- [ ] 先看一次 **「評量名稱與題數」** 與檔案欄位數有沒有對得上。

## D. 上傳（管理後台 →「批次上傳」）

1. 步驟 1：選擇評量（**再確認一次是對的那份**）。
2. 步驟 2：按「選擇 CSV / Excel 檔案」，選檔。
3. 步驟 3：看**預覽**。
   - 紅字「**不能匯入**」：整個檔案被擋下，通常是評量選錯或檔案是別份評量的。照說明修，不要硬傳。
   - 黃字警告：忽略的欄位等，看過再決定。
   - 「**解析警告**」列出被略過的列（缺題、Email 錯、分數超出範圍）：**要修好重傳，不要放著**。
   - 預設**缺題的列不會匯入**；如果確定要匯入缺題的資料（例如紙本漏填），勾「允許缺題」，但缺的題會被當成沒作答，影響分數。
   - 預覽的「有效資料 N 筆」要和你預期的列數**一致**。
4. 按「**確認匯入 N 筆到〈評量名稱〉**」。結果頁會顯示成功筆數與自動建立的帳號數。
5. 記下結果：筆數、帳號數。

**課前／課後**：要做前後測比較的資料，請在 `phase` 欄標記 `pre`／`post`（同一人兩列，一列課前、一列課後）；班級總覽的「前測分布與前後測比較」就能直接用。沒有標記的列視為前測。同一人同一階段重複時以檔案中較後面的那一列為準。舊的範本（沒有 `phase` 欄）仍然可以上傳。

## E. 建班與加成員

1. **教練後台 → 建立班別**：選**專案範本**（評量會自動鎖定、公司名稱自動帶入）。沒有範本時才自選評量，並再確認一次。
2. 加成員：「成員與設定」搜尋姓名加入。匯入的帳號沒有密碼，**要用管理員身分才能直接加入**（教練只能發邀請，而邀請要本人收信接受）。
3. **成員要加誰**：
   - 一般評量（自評）：所有受測者都加。
   - **360°：只加「受評者」**（有自評的人）。評分者不需要加入班級，他們給的分數會依受評者掛上，360 分析都看得到。
4. 設定班級的施測期間（開始日、結束日）。只要看資料不需要作答，期間不影響檢視。

## F. 上傳後檢查與產出

1. 打開班級「**總覽**」，先看最上方有沒有黃色「**請先確認這個班的資料**」警告：
   - 「成員有批次匯入的作答屬於別份評量」→ 班級或匯入的評量選錯了，到 G 處理。
   - 「匯入的作答有構面完全沒作答」→ 檔案缺題或評量選錯，到 G 處理。
2. 核對數字：成員人數、每人的總分與落點、360° 的他評人數與類別是否和原始資料一致（抽查 2–3 位）。
3. 產出報告：
   - **個人報告**：成員比較表「查看」→「產出報告」。
   - **360° 完整報告**：成員比較表的「360° 報告」（該成員有他評時），預覽後「列印 / 存為 PDF」。
   - **班級報告**：總覽上方「產出班級專業分析報告」。
4. 需要讓學員自己登入看：**管理後台 →「用戶管理」→ 該用戶「重設密碼」**，把連結給本人（占位 Email 的帳號不適用）。

## G. 出錯了怎麼辦

匯入的結果是匯入當下算好的快照，**不能就地修改**，要移除後重匯：

1. **管理後台 →「批次上傳」→ 評量選錯的那份 →「移除…已匯入的作答」**。
2. **先看彈出的名單**（筆數與受評者）。名單裡有別的專案的人，就不要確認。
3. 確認後只會移除「批次匯入」的作答；學員自己作答的不受影響；匯入時建立的帳號會保留，重匯會沿用。
4. 修好檔案（或選對評量），回到 D 重新上傳。班級選錯評量的話，刪掉班級用範本重開。

## 不要做的事

- 不要把題數、題目不一致的資料傳進別份評量（系統會擋，但不要試）。
- 不要自己把反向題的分數換算過再填。
- 不要在 Excel 裡改欄位名稱。
- 不要在還沒確認評量對不對時就按確認匯入。
- 不要把客戶的 Email、姓名、分數放進 Git、Issue 或對話貼文；匯入檔案用完後依客戶約定保存或刪除。
- 大量匯入前，可以請有 VPS 權限的人先跑一次 `bash deploy/backup.sh`（部署時會自動備份，單獨匯入不會）。
