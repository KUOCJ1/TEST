# 新領導力評量：平台工程規格（v0.1，草案）

> 本文件只寫規格，**不含任何平台程式改動**。待專家審題與認知前測完成、題目定稿（v0.3 以後）再依第 10 節分 Sprint 實作。
> 範圍決定：L9D 不動，新評量獨立並存（見第 10 節）。
> 標記：📎 已對照現有程式碼確認；🧮 本案提出的設計提案；⚠️ 數值為暫定，需試測資料校準。

## 1. 目標與原則

1. 新增一份原創的領導力評量，**作為獨立的新題庫與 L9D 並存**。L9D 完全不動（設定、計分、啟用狀態、對外文案、歷史資料皆維持原樣）。是否取代或移除 L9D，待新評量完整且穩定後另行決定，不在本規格範圍。
2. 沿用平台既有的「設定驅動」模式：新評量 = 一支設定檔 + 資料庫登錄一筆，其餘元件盡量不改。
3. 自評與 360° 同為核心；組織診斷用精簡版、主管發展用完整版；接班意願另開問卷，不混入能力分數。
4. 分數解讀以「構面輪廓＋張力平衡＋自評與他評落差」為主，**不做單一總分排名**（總分仍會算，僅為相容既有格式）。

## 2. 現有平台盤點（📎 對照原始碼）

| 項目 | 現況 | 對新評量的影響 |

| 題庫設定形狀 | `ID, NAME, SCALE_*, DIMENSIONS[{questions,subDimensions}], ALL_QUESTIONS, LEVELS, dimensionRating, COMMENTARY, SUPPORTS_360, RATER_PROMPT` | 沿用；需新增欄位見第 3 節 |

| 題庫文字後台覆寫 | `overrides.js` 就地修改設定物件，只覆寫白名單文字欄位 | 新設定須遵守「載入時不把文字複製到別處快取」 |
| 隱私政策 | 文字與程式行為須一致，`POLICY_VERSION` 前後端一致 | 新增資料用途（見第 8 節）要同步改政策並提升版本 |

## 3. 設定檔設計（🧮）

檔名建議 `src/survey/data/assessments/leadership-fast-last.js`；**ID 暫定 `leadership-fl`**（待品牌/商標檢索後決定，ID 一旦有資料就不能改）。

```
ID, NAME, NAME_EN, ABBR, DESCRIPTION
SUPPORTS_360 = true
RATER_PROMPT = '的領導行為表現'
SCALE_MIN = 1, SCALE_MAX = 5
SCALE_LABELS = [從不, 很少, 有時, 經常, 總是]      // 頻率
NA_VALUE = 'na'                                      // 僅他評版可選
LOOPS = [{ id:'fast', name:'快環', dimensionIds:[...] }, { id:'last', ... }]   // 對應 L9D 的 LAYERS 概念，但獨立定義
DIMENSIONS = 8 個，每個含 id, index, name(四字), subtitle(英文動詞), loop, color,
             subDimensions[{id,name(四字)}], questions[]
問題欄位 = { id, text, textOther, reversed, subId, form:['full'|'short'], observability:'normal'|'low',
             ai:boolean, pole?:'focus'|'flex'|... }
TENSIONS = [{ id, dimensionId, poleA:'focus', poleB:'flex', nameA:'聚焦', nameB:'彈性' }, ...] // 共 4 組
FORMS = { full:{...}, short:{...} }                  // 以題目的 form 欄位過濾
```

設計重點：
- `ALL_QUESTIONS` / `TOTAL_QUESTIONS` 必須依「目前選用的版本」（完整／精簡）計算。目前這些是模組層常數，**需改成函式或由 `FORMS` 衍生**——這是對既有計分模組的第一個結構性改動（見 10 節 S13）。
- 文字欄位（`text`、`textOther`、名稱）列入後台覆寫白名單；`reversed`、`pole`、`form`、`observability` **不可**被覆寫。
- 題目資料來源是 `docs/leadership-new/items-candidates-*.json`，實作時由腳本轉成設定檔，避免手工抄寫出錯，並重跑相似度檢查。

## 4. 計分（🧮，⚠️ 切分點暫定）

### 4.1 基本計算（與既有一致）
- 反向題：`有效分 = 6 − 原始分`。
- 子面向平均 → 構面平均（1–5）→ 環平均（構面平均再平均）。
- `total`：為相容 `validateResultShape` 仍輸出 = 有效分加總（精簡版 32–160、完整版 69–345）；**報告不以總分為主角**，也不做總分分級。

### 4.2 構面等級
沿用 5 級文字 `精熟／熟練／發展中／萌芽／待啟蒙` 的**結構**，但切分點 ⚠️ 不直接沿用 L9D 的 4.2／3.4／2.6／1.8（該切分點是為同意度量表設計）。初版暫以相同切分點上線僅供試測，**正式切分點待試測資料（分布、專家設標）決定**。

### 4.3 張力平衡指標（四組）
每組張力有兩端 `A`、`B`（例：聚焦／彈性），各自算端平均 `a`、`b`（1–5）。
- **強度** `s = (a + b) / 2`：兩端合計用得多不多。
- **偏態** `d = a − b`：偏向哪端。
- **平衡度** `balance = 1 − |d| / 4`，範圍 0–1。
- **類型**（⚠️ 切分暫定）：
  - 兩端都高（`a ≥ 3.5` 且 `b ≥ 3.5`）→「兼顧」
  - 兩端都低（`a < 2.5` 且 `b < 2.5`）→「兩端皆弱」
  - 否則 `|d| ≥ 1.0` → 「偏 A」或「偏 B」
  - 其餘 →「略偏 / 尚可」
- 反向題先轉換為有效分再歸端；**張力端的題數須相等**（已在題庫設計時確保；設定檔載入時以測試檢查）。
- 解讀文字原則：「偏重」不是缺點，要描述「在什麼情境下這個偏重可能變成限制」。
- 精簡版：只在**構面層級**呈現張力，細項不解讀（題數太少，見 02 文件）。

### 4.4 「無法判斷」與缺漏
- 僅他評版、且題目 `observability: low` 才顯示「無法判斷」選項（`NA_VALUE`）。
- `na` 視為**缺漏**而非 0 分：不計入分子與分母。
- 完成條件：自評須全部作答；他評每個構面至少 **60% 題目有有效分**（⚠️ 暫定），且至少 80% 總題數；否則該份不納入彙整並提示補答。
- 此項需改 `scoring.js` 的 `isComplete`、`answeredCount` 與提交流程；**現行邏輯將非 1–5 的值視為未答，必須先加參數化的「允許 na」才能支援**。

### 4.5 自評與他評落差
- 他評彙整只在「他評者人數達門檻」時計算（7.2）。
- 每個構面 `gap = 自評平均 − 他評平均`：
  - `gap ≥ +0.8`（⚠️）→「可能的盲點」（自評高於他評）
  - `gap ≤ −0.8`（⚠️）→「隱藏的優勢」
  - 否則「大致一致」
- 另輸出整體 `誠實落差指數` = 各構面 |gap| 平均，供教練參考；**不在本人報告用評判語氣**。
- 切分點 ⚠️ 需用試測資料的實際分布校準，不可直接沿用。

### 4.6 結果物件（寫入 submission.result）
```
{ total, max, level,                          // 相容既有
  dimensions:[{id,score,max,average,rating,subs:[...]}],
  loops:[{id,average}],
  tensions:[{id,a,b,strength,skew,balance,type}],
  form:'full'|'short', answeredCount, naCount, itemVersion }   // itemVersion 用於日後換版比較
```
`itemVersion` 必須寫入：題庫改版後，舊結果要能識別其對應的題目版本（見第 9 節）。

## 5. 作答介面

- 每頁按構面分組（8 頁），顯示進度與構面名稱；張力成對題**不相鄰排列**（避免被看出配對而影響作答），題目順序在構面內隨機但同一受測者固定。
- 頻率量表用文字＋數字；他評版顯示「無法判斷」於低可觀察題。
- 自評開頭說明「這是行為頻率，不是能力高低；沒有標準答案」。
- 手機版需可單手作答；沿用既有 `QuestionCard` 樣式與 AA 對比規範。
- 完整版約 69 題、精簡版 32 題；在畫面顯示預估時間（⚠️ 待前測實測，自評完整版先估 15–20 分）。

## 6. 報告（個人）

1. 八構面雷達圖（沿用 `RadarChart`，需支援 8 軸）；兩環各一段平均。
2. 四組張力圖：兩端各一刻度＋平衡度標記，附一句「在什麼情境可能變成限制」。
3. 自評 vs 他評並列圖（人數達門檻時）；盲點／隱藏優勢清單（最多各 3 項）。
4. 敘事評語：沿用 `COMMENTARY` 機制；**每構面 × 3 級 × 多變體**的文字需原創撰寫，量大（約 8 × 3 × 3 = 72 段以上），列為獨立工作（S15）。
5. 人機協作題群組成一個「人機協作剖面」小節（9 題），不單獨成構面。
6. 列印版（`PrintableReport`）需同步。

## 7. 360° 與匿名

### 7.1 評分者類型
沿用 `self／manager／peer／subordinate`。

### 7.2 最少評分人數門檻（🧮，**現況缺口**）
現況：本人看到的他評一律匿名，但**沒有人數門檻**，若某類只有 1 位，等同可辨識。
提案：
- `peer`、`subordinate` 各類 **≥3 位**才顯示該類彙整與逐構面分數；不足則併入「他評合計」，合計仍須 **≥3 位**才顯示，否則整段隱藏並提示「回覆者不足」。
- `manager`：通常只有 1 位，無法匿名，**必須在邀請與作答畫面明示「你的回答對受評者可辨識」**，並由受評者與主管同意後才顯示。
- 本人永遠看不到單一評分者的逐題作答（現況已排除 `answers`，維持）。
- **教練／管理者還原身分**（現況有 `canDeanonymize`）：須在評分者作答前告知「教練可能看到你的身分」，並在政策中說明；建議預設改為教練也只看彙整，還原需管理者並留稽核紀錄（⚠️ 這是產品決策，待你確認）。

### 7.3 評分者邀請
現行評分者須為同班成員。企業客戶的 360° 常需跨部門、跨班級的邀請，此限制可能不夠用 → 待確認是否需要「受評者建立評分者名單＋以連結邀請」的新流程（涉及帳號、同意、郵件，工作量大，列入 S16 的決策點）。

## 8. 組織診斷（群體彙整）

- 單位：班級或「診斷專案」（一組受評者）。
- 呈現：八構面平均、兩環平均、四組張力的**分布**（例：各偏態類型人數占比）、自評—他評落差的群體分布、最強與最弱構面。
- 匿名門檻：群體 **≥5 位受評者**才顯示（⚠️ 暫定）；子群組（部門、層級）切分後仍須 ≥5，否則合併或隱藏。
- 不輸出個人排名；不提供「某個人」的群體外比較。
- 文字須強調：群體報告描述的是「這群人的行為模式」，不是組織文化的診斷結論。
- 與 `GroupNarrativeReport` 現有機制對齊，新增段落模板。

## 9. 接班補充問卷（獨立評量）

- 獨立 `assessmentId`（暫稱 `succession-readiness`），**不併入領導力分數**。
- 內容：企圖心、意願、可接受的職務範圍（scope）、流動意向等；題目另行原創設計，不在本規格範圍。
- 敏感度高（含離職傾向）：
  - 僅受評者本人與**被授權的客戶管理員**可見，教練預設不可見（⚠️ 待確認授權模型）。
  - 組織診斷用途只輸出匯總，≥5 人。
  - 政策與同意文字必須新增（用途、保存、可見對象），**提升 `POLICY_VERSION`**，並重新取得同意。
- 與領導力評量的連結：報告以「接班矩陣」並列兩軸，但分數不合併。

## 10. 與 L9D 並存（🧮）

使用者決定（2026-10-17）：暫時不動 L9D，新評量獨立上線；待新評量完整穩定後再考慮取代或移除。

1. **新增、不改寫**：新評量用新 ID；`leadership-9d` 的設定檔、`KNOWN_ASSESSMENTS` 項目、`enabled` 狀態、行銷與說明文字**一律不改**。
2. 兩份評量在平台上是兩張獨立卡片，班級建立時可各自選用；教練端要能清楚分辨兩者，名稱需避免混淆。
3. 歷史趨勢與跨梯次分析：不同評量以 `assessmentId` 分開，**不混成同一條趨勢線**（現行機制已按評量分流，S14 時以測試確認新評量不被誤併）。
4. 對外文案：新評量加入首頁／FAQ／說明書時只新增，不刪除 L9D 內容。
5. 日後若要取代 L9D（屬未來獨立決策）：才處理停用、文案替換、歷史資料顯示等，並先做備份與還原演練。
6. 共用程式（`scoring.js` 等）的改動必須讓 L9D 的既有結果完全不變，以現有測試與快照比對守住。

## 12. 測試計畫

- 單元：計分（反向、缺漏、na、60% 規則）、張力類型邊界值、落差分類、門檻（2 位 vs 3 位、4 人 vs 5 人群體）、版本過濾。
- 屬性測試：任意 na 位置下平均值落在 1–5；張力兩端題數相等。
- 回歸：既有 361 個前端測試與 168 個後端測試不得變動結果；新增快照比對 L9D 的舊結果在新計分程式下不變。
- 後端：提交含 na 的結果仍通過 `validateResultShape`；權限（本人／教練／管理者）對門檻與還原的行為；停用評量後的既有班級行為。
- E2E：完整版與精簡版各跑一輪、360° 三位他評者達門檻、不足門檻時的顯示、列印版。
- 無障礙：8 頁作答頁與圖表加 axe 檢查。
