# 改善計畫（2026-11 第三輪）：Sprint 30–35

> 來源：2026-11-16 手機走查（34 個畫面、逐屏截圖）後，產品負責人要求：
> ① 先修好還沒修的問題；② 把還沒做完的手機與電腦介面做完整，新增的功能與連結同步測試；③ 持續發展學員與教練的新功能。
> 原則：沿用既有決定（教練只看人數、不外部 AI、隱私規則不放寬）；除非要產品負責人決定或環境不通，否則連續執行。

## 預設決定（可事後推翻）

| 議題 | 預設 | 理由 |
|---|---|---|
| 360° 報告同儕／部屬少於 3 位 | 不單獨呈現，只併入「他評合計」；主管（通常 1 位）不套用 | 與教練端覆蓋率面板的 3 位門檻一致；主管角色本身公開 |
| 走查驗收 | 數字（溢出、字級、觸控）＋**逐屏看截圖** | 本輪的問題沒有一個是數字量出來的 |
| 新功能 | 只用站內既有資料與規則式文字；不接外部服務 | 隱私與成本；與既有決策一致 |

## Sprint 31　手機走查補齊（✅ 2026-11-16）

結果：目標回報、課後問卷、邀請連結已納入走查（60–63）並逐屏檢視，沒有新增問題；他評作答流程（嚴格隱私題庫）由既有 e2e `compass-360-flow` 覆蓋，手機尺寸未另跑。

範圍：走查腳本尚未涵蓋的畫面——發展目標（建立、回報、延後）、他評作答（邀請連結進來）、課後問卷、邀請入班（連結／登入後兌換）、個人設定、AI 小幫手浮動按鈕與底部導覽的遮擋、評測作答中斷續答。
驗收：每個畫面有截圖、逐屏檢視；整頁溢出 0、觸控目標與字級達標；發現的問題當場修；新增的走查項目有 e2e 或單元測試守住。

## Sprint 32　桌機走查與連結檢查（✅ 2026-11-16）

結果：`npm run audit:desktop` 38 個畫面；修了雷達圖圖例重疊、教練頁寬度、「我的分析」空狀態缺 `<main>`；`e2e/entry-links.spec.js` 4 條。

- 桌機（1280×800）走查所有角色畫面，補齊桌機版型的缺口（寬螢幕留白、表格、側欄導覽、報告預覽）。
- 連結檢查：站內所有入口（導覽、卡片按鈕、提醒信連結 `?goal=`／`?invite=`／`?join=`、報告內跳轉）逐一點到、確認落在正確畫面；寫成一支 e2e，之後新增入口要補。
驗收：桌機走查無水平溢出、無被截斷的文字；連結 e2e 綠。

## Sprint 33　學員：我的下一步與進步摘要

- 首頁「我的下一步」單一卡片：依狀態只顯示一件事（還沒作答／該回報目標／可以複測／看學習資源），取代現在分散在各處的提示。
- 進步摘要：複測後把前後兩次並列（核心構面變化、進步最多的一項、目標完成數），可存成圖／列印一頁。
- 約束：只用本人資料；沒有複測時不出現；手機優先。
驗收：四種狀態各有單元測試；手機與桌機截圖檢視；e2e 走完「作答→設目標→回報→複測→看到進步」。

## Sprint 34　教練：課堂模式與備課摘要

- 課堂模式：投影用的班級畫面（大字、無姓名、只有彙總與構面落點），一鍵進入／離開；少於 3 人不顯示分布。
- 備課摘要：依班級較弱構面，列出建議的課堂活動與討論題（規則式，沿用 `dimensionInsights.js`／`goal-starters.js`），可複製成講義大綱。
- 約束：教練不得因此看到個人名單或「誰沒做」。
驗收：隱私測試（無姓名、<3 人隱藏）；手機（教練在教室用平板／手機）與桌機截圖；e2e。

## Sprint 35　整合收尾

使用手冊（章節＋截圖＋PDF）、`CHANGELOG.md`、`CLAUDE.md` 速查、部署清單與回退點；全套測試（lint／unit／後端／e2e／走查）一輪。

## 風險與反向觀點

1. 「更多功能」會稀釋「看清落點，走好下一步」的主軸；Sprint 33 的原則是**收斂**（一張卡一件事），不是再加入口。
2. 課堂模式若被拿去投影含少數人的班級，仍可能被推回個人；門檻與提示文字要寫清楚。
3. 沒有真機：觸控、鍵盤彈出、iOS Safari 捲動仍需產品負責人實測（清單見 `docs/MOBILE_APP_PLAN.md`）。
