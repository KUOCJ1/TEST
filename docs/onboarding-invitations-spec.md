# 邀請制入班（Sprint 19）規格

2026-10-19 使用者決策：先在後台把學員的 Email 編入班級，再發出邀請連結（含邀請碼），學員用連結完成註冊與填資料。
公開註冊與掃碼報到**先保留**，等邀請制成熟後再評估關閉。

## 為什麼

- 名單由後台掌握；學員少填、少出錯（Email、姓名、班級都已帶入）。
- **修補一個缺口**：舊做法把未註冊的 Email 放在班級「待加入名單」，對方註冊時只比對 Email 就自動入班，但沒有驗證註冊者擁有那個 Email——任何人可以搶先用別人的 Email 註冊並入班。邀請碼綁定單一 Email、一次性，持有碼即證明收到了信。
- 後台看得到每個人的狀態（已邀請／已加入／已過期）、可重寄、重新產生、撤銷。

## 資料

`memberInvites` 集合（`server/src/lib/memberInvites.js`）：

| 欄位 | 說明 |
|---|---|
| id | |
| groupId | 所屬班級 |
| email / name | 受邀者（Email 小寫；姓名由教練登錄，註冊時可修改） |
| code | 10 碼邀請碼（字元集同報到代碼，不含易混淆字）；存明碼，讓教練隨時可複製連結 |
| status | `invited`（尚未使用）／`joined`（已註冊或已認領）／`revoked` |
| expiresAt | 建立或重新產生後 14 天 |
| createdBy / createdAt | |
| lastSentAt / sendCount | 寄信紀錄（沒設定 SMTP 就一直是空） |
| joinedUserId / joinedAt | |

「已過期」不是儲存的狀態，而是 `status==='invited' && expiresAt < now` 計算出來的。

## 規則

1. 邀請連結：`{APP_URL}/?invite={code}`。碼也可以在登入頁／登入後的首頁手動輸入。
2. **註冊**帶 `inviteCode`：Email 一律以邀請上的為準（前端鎖定、伺服器強制，不信任請求內容）；姓名可改；
   成功後自動入班、邀請標記 `joined`，帳號記 `emailVerifiedAt`（持有碼＝信箱驗證）。
3. **登入**帶 `inviteCode`：密碼正確後，邀請的 Email 必須等於這個帳號的 Email 才會入班（已有帳號的人也能用邀請連結加入）。
4. **登入後兌換**：`POST /api/invites/redeem {code}`；Email 不符回 403，並說明「這封邀請是寄給另一個 Email」。
5. 一次性：`joined`／`revoked`／過期的碼不能再用，錯誤碼分開（`INVITE_USED`／`INVITE_REVOKED`／`INVITE_EXPIRED`／`INVITE_NOT_FOUND`），前端各自給白話說明。
6. **不再依 Email 自動入班**：註冊或登入本身不會認領任何邀請。
7. 邀請的班級若使用高敏感評量，與其他入班方式一樣：本人註冊時已勾選同意現行政策。
8. 公開查詢 `GET /api/public/invite/:code`（有限流）只回班級名稱、教練、受邀者姓名與 Email、到期日；不含成員或成績。
9. 管理員與教練都能管理自己班的邀請；管理操作寫稽核（建立、重新產生、撤銷、寄送）。

## 教練／管理端

- 「成員與設定」新增「學員邀請」區：列出每位的狀態與到期日，動作有：複製連結、重新產生、撤銷、寄送邀請信；整批：複製全部連結、匯出連結清單（CSV）、寄送全部尚未寄出的邀請。
- 名單匯入（貼 Email）：已有帳號者維持原行為（管理員直接加入、教練發班級邀請）；未註冊者建立邀請並顯示連結。
- SMTP 未設定時「寄送」按鈕停用並說明；其餘功能不受影響（先用複製連結／匯出，設好 SMTP 後再寄信）。
- 催交提醒信：對「尚未加入」的邀請改附其專屬邀請連結。

## 舊資料

啟動時把各班 `pendingMembers` 轉成邀請（新碼、14 天），並清空 `pendingMembers`。
這些人要由教練從後台取得連結再寄出；舊的「註冊後自動入班」不再運作。

## 驗收

- 教練匯入 Email → 看到每人連結與狀態；用連結註冊：Email 鎖定、姓名預填、完成後在班上；同一連結再用被拒；過期／撤銷／重新產生行為正確。
- 沒有邀請碼自行註冊的人**不會**被自動編進任何班級。
- 掃碼報到、公開註冊照舊可用。
