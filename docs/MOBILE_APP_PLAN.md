# 手機 App 化計畫（PWA 路線）

狀態：**計畫已定稿，決定 D1–D5 已由使用者確認（照預設）；Sprint M0 已完成，M1、M2 完成，M3 已實作（CI 確認中），M4 起待執行**（2026-11-13）。
這份文件是給「接手執行的人或另一個 AI 對話」看的，讀完就能直接開工，不需要回頭翻對話紀錄。

## 1. 目標與範圍

**目標**：讓客戶、學員、教練、講師在手機上用起來像 App、覺得好用。

**做法**：不重寫、不上架商店。沿用現有 React 前端與後端，走 PWA（從瀏覽器「加到主畫面」安裝），把手機上的介面打磨到位。

**不做**：
- 不上 App Store／Google Play，不做 Capacitor 或 React Native。
- 不改後端架構、資料庫、部署方式。
- 不改任何計分、題庫結構、隱私規則。
- 管理後台不做完整的手機版（批次上傳、題庫內容編輯留在電腦上做），只保證手機上「看得到、不壞版」。
- 桌機版面不變：手機的調整一律用 `sm:` 斷點以下的樣式，不動 `sm` 以上的呈現。

**已經有的基礎**（不用再做）：
- PWA 安裝設定完整：`vite.config.js` 的 `VitePWA`（manifest、圖示、`display: standalone`）、`index.html` 的 iOS 主畫面設定。
- 學員端手機底部分頁列（`src/survey/AppShell.jsx`，作答時自動隱藏）。
- 作答畫面的選項按鈕夠大；登入、QR 報到頁在手機上乾淨。
- 走查的 29 個畫面**沒有任何整頁水平溢出**。

## 5. 執行計畫

每個 Sprint 都能獨立上線。順序是 M1 → M2 → M3 → M4 → M5；M3 與 M4 可以對調。

### Sprint M1：共用基礎與防護網

目的：先修「每一頁都有」的問題，並建立會擋部署的手機測試，後面的 Sprint 才不會改壞。

| 工作 | 做法 |
|---|---|
| M1-1 手機版面測試 | 新增 `e2e/mobile-layout.spec.js`（手機 viewport 390×844、`isMobile`、`hasTouch`）。對學員首頁、作答、結果、我的分析、教練總覽、登入頁斷言：整頁沒有水平溢出（`scrollWidth <= innerWidth`）、底部導覽存在（作答頁除外）、主要按鈕短邊 ≥ 44px。**加入 `npm run test:e2e`，CI 會擋** |
| M1-2 觸控目標規範 | 在 `index.css` 訂出手機上的最小觸控尺寸：`sm` 以下時 `btn-sm`、chip、文字連結的可點範圍 ≥ 44px（文字連結用 padding 擴大點擊區，不改視覺字級）。先改共用樣式，再處理個別元件 |
| M1-3 AI 小幫手按鈕（F2） | 手機上縮小、不遮內容：改成較小的圖示並貼齊底部導覽上緣；作答頁、報告預覽、有底部固定操作列的頁面隱藏；頁面底部加足夠的 padding 讓最後一張卡片不被蓋住 |
| M1-4 進度列（F6） | 先在手機實機或模擬器確認是否被頁首蓋住；若是，把 `ProgressBar` 的 `top` 設成頁首高度，或在作答時把進度併進頁首 |
| M1-5 小字（F8） | 底部導覽標籤、量表兩端說明提高到 12px 以上 |

**驗收**：
- `e2e/mobile-layout.spec.js` 通過，且在 CI 裡執行。
- `npm run audit:mobile`：訪客＋學員畫面（01–23）的過小觸控目標從 135 降到 **20 以下**，剩下的逐一列在本文件第 7 節並說明原因。
- 作答時捲動到第 10 題，進度列看得到。
- 任何一頁的最後一個元素都不被 AI 小幫手按鈕蓋住。
- 桌機（1280×800）截圖與改版前相比沒有非預期差異（`npm run manual:screenshots` 比對）。

## 6. 每個 Sprint 都要做的事（完成的定義）

1. **測試**：`npm run lint`、`npm test`、`npm run build`、`cd server && npm test` 全過。
2. **完整 e2e**：`npm run test:e2e` 全過。這個雲端環境要加上瀏覽器路徑：
   `PLAYWRIGHT_CHROMIUM_PATH=/opt/pw-browsers/chromium npx playwright test`。
   **改到任何畫面都要跑完整 e2e，不能只跑單元測試**（前幾次 CI 失敗都是因為沒跑）。
3. **走查量測**：`PLAYWRIGHT_CHROMIUM_PATH=/opt/pw-browsers/chromium npm run audit:mobile`，把數字填進第 7 節。
4. **列印不能壞**：動到報告相關元件時，確認個人報告與 360° 報告轉成 PDF 的頁數不變、沒有空白頁。
5. **桌機不能變**：手機樣式只加在 `sm` 以下。
6. **文件**：`CHANGELOG.md` 最上面補一段；本文件第 7 節更新進度；必要時更新 `CLAUDE.md`。
7. **上線**：推到 `claude/ai-assessment-survey-4vhjun`，**CI 全綠後**才給使用者部署指令（格式見 `CLAUDE.md`「更新版本到 VPS」，並加上 commit 檢查）。雲端容器不能直接部署到 VPS。
8. **實機確認**（請使用者做，AI 做不到）：iPhone Safari、iPhone 主畫面安裝版、Android Chrome、LINE 內建瀏覽器，各走一次該 Sprint 改到的流程。

不能碰的東西：計分（`utils/scoring.js`）、題庫結構（會被結構指紋測試擋下）、隱私規則（`server/src/lib/compassPrivacy.js`、課後問卷只給彙總）、L9D 的題目。細節見 `CLAUDE.md`。
