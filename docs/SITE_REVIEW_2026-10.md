## 2. P0：啟用領導力羅盤之前必修

### P0-1 ✅ 任何登入者可對任何人送他評，伺服器不驗關係（`server/src/routes/submissions.js:13-61`）
- 現況：`rateeId`／`raterType` 只做型別檢查；不驗受評者存在、不驗與評分者同班、不驗評量是否啟用。評分者不在任何班級時，重複檢查與階段鎖全被略過。審查者以腳本實測：不同班的攻擊帳號對同一人連送 3 筆 peer 都回 201，受害者報告出現「3 位同儕彙整」。
- 影響：一個人可偽造「3 位同儕」繞過匿名門檻、灌水、冒充「上級」（受評者同意共享後直接顯示）。
- 改善：
  1. 他評須驗證評分者與受評者同屬某個該評量的班級，且班級在進行中（或改成受評者／教練建立「評分邀請」，評分者只能對被邀請的人送一次）。
  2. 以不同使用者（distinct userId）計數，不是筆數；(評分者, 受評者, 類型, 階段) 唯一，不論有沒有班級。
  3. 補負向測試（非同班不得評、不存在的受評者、重複送出）。現有測試的 peer 提交本身就沒有同班關係，等於把此行為當正常。

### P0-2 ✅ 彙整可用「相減」還原單一評分者（`server/src/lib/compassPrivacy.js:108-113`）
- 現況：同儕 ≥3 時單獨輸出；同時又輸出「同儕＋部屬（＋已同意的上級）」合計。兩者相減即可算出未達門檻類別的分數（審查者實測：同儕 3 人各 6 分、部屬 1 人 2 分，由 `peer` 與 `others` 的平均反推出部屬為 2 分）。回傳的 `count` 讓計算更容易。
- 改善：輸出 `others` 時，若有任何子類別被單獨輸出，就要求「剩餘」人數也 ≥3，否則不輸出 `others`；或改為只輸出互斥分群。`count` 改為「≥3」或不回傳。補測試（含上級同意後的情況）。同步檢查個人報告的 `others` 顯示邏輯。

### P0-3 ✅ 管理員總覽繞過「理由＋稽核」（`server/src/routes/admin.js:169-178`）
- 現況：`GET /api/admin/overview` 回傳全部作答（只去掉 answers），未套用 `stripRaterDetails`，羅盤的他評帶著評分者 userId／姓名與個別分數。政策與 CLAUDE.md 都寫「管理員還原須填理由並留稽核」，此路徑沒有。批次匯入同理。
- 改善：admin overview 也走 `stripRaterDetails`，還原只走 `ratee?deanonymize=1&reason=…`；補測試。

### P0-4 教練可用「把人加進自己的班」還原匿名評分者（`routes/coach.js:55-70, 77-86, 97-109, 349-379`）
- 現況：教練可搜尋全站使用者並加入自己的班，不需對方同意、無稽核。加入後原本看不到的、由該人送出的羅盤他評會出現在總覽（匿名但帶受評者 id），前後比對即可得知「X 評了 R」。同一機制也讓教練能讀到被加入者所有題庫的成績。
- 改善：加人須對方同意（邀請／接受），或限制搜尋範圍；嚴格隱私題庫的可見性只依受評者，不依評分者是否在班；成員加入／移除寫稽核。

### P0-5 停用的評量仍可提交、建班（`submissions.js:24`、`coach.js:111`）
- 現況：伺服器不檢查 `enabled`，任何註冊用戶直接打 API 就能提交羅盤／接班準備度（高敏感的職涯意向），繞過「啟用前須先同意新政策」的設計。
- 改善：提交與建班都驗證評量存在且已啟用；補測試。

### P0-6 政策同意閘門只在前端（`server`：僅 register 與 `/auth/consent` 檢查）
- 現況：既有用戶可略過畫面直接打 API。政策升到 `2026-10-18` 後，「先同意才能使用」只是 UI 行為。
- 改善：加 `requireConsent` 中介層（`/auth/*`、公開頁除外），補伺服器端測試；或在政策文字改為如實描述。

## 4. P2：排程修

**安全與穩健**
- 儲存層每次寫入「刪全表重灌」，寫入失敗不回滾記憶體；無上限寫入端點（`learning-resources/track-click`、無班級者的提交）。短期課程規模可接受，成長後改逐筆 upsert＋交易。
- AI 聊天代理：只驗證陣列與筆數；可注入 `role:system`；無每使用者額度、無上游逾時、客戶端斷線不中止。加角色白名單、長度上限、每日額度、逾時與 abort。
- `/api/health?deep=1` 免登入且不限流，每次對外發請求。限管理員或加快取。
- 登出不撤銷 token（被偷的 cookie 7 天內有效）；API client 無逾時、無 401 處理（過期後介面仍顯示已登入）。
- 其他：註冊回 409 可列舉帳號；`name`、密碼、goals id 無長度上限；`readingList.url` 與學習資源連結未限制 http(s)（`javascript:`）；`/coach/user-search` 可批次蒐集 Email；`/assessments/:id/benchmark` 對任意 id 計算並快取；`/submissions/me` 與 `/submissions/ratee` 對「未發布」的處理不一致 ⚠️；伺服器信任前端算好的 `result`（只驗形狀）。
- 補安全標頭（CSP、X-Content-Type-Options、Referrer-Policy；Express 加 helmet 並關閉 `x-powered-by`）；`index.html`、`sw.js` 設 `no-cache`；`gzip_types` 補 `text/javascript` ⚠️；systemd unit 加強化選項。

**前端體驗與無障礙**
- 教練班別列表載入失敗被靜默吞掉；快速切換班別有競態（慢回應覆蓋）。
- 對話框（HelpModal、MemberDrawer、ChatBot 面板）缺焦點移入／陷阱／還原；表單欄位只有 placeholder；分頁元件 ARIA 用法不正確；分段圓點與關閉鈕約 28px；行銷頁多數缺 `<main>`；手機版頂部導覽直接隱藏。
- 暗色模式在 React 掛載後才套用（閃白）；字型多家族阻塞載入；首頁預載 85KB 的全題庫 chunk。
- SEO：只有一組通用 title／description，無 OG／canonical／robots.txt／sitemap；未知路徑回 200（soft 404）；行銷頁為純 CSR。若要自然搜尋效益，考慮行銷頁預先渲染。
- 其他小項：`QuestionCard` 數字鍵未排除修飾鍵；`LoginPage` 從網址預填姓名／Email 後未清網址；`joinCode` 登出再登入會重複觸發；`ContentProvider` 逾時 4 秒後靜默退回舊文字；`BatchUploadSection` 解析前無檔案大小檢查；管理後台一次載入全站作答，無分頁。

**測試與 CI**
- `app-flow.test.jsx` 偶發失敗已重現（lazy 元件編譯在並行時變慢逾時）。不要再加大 timeout：改為 `beforeAll` 預先載入 lazy 元件，或限制並行數；CI 可暫加 `--retry=1`。
- 缺口：羅盤與接班準備度完全沒有 E2E；E2E 全在 dev server＋記憶體資料庫，未驗證正式 build、PWA、檔案型 SQLite（WAL）；遷移（舊 JSON→SQLite、損毀檔、主鍵衝突）幾乎無測試；L9D／DISC／識己計分邊界無直接測試；越權與 360° 負向案例（見 P0）。
- CI：只在兩個功能分支 push 觸發（其中一個疑似過期），無 `pull_request` 觸發；整個 job 具 `contents: write`；Action 只釘 tag 不釘 SHA；無 `npm audit`、無 concurrency。
- 文件小矛盾：`DEPLOYMENT.md:10`「備份只要複製檔案」與其後「不要直接 cp」互相矛盾；`CLAUDE.md` 寫的 `DB_PATH` 預設與程式不符；`server/package.json` 描述仍是 JSON 儲存；`DEPLOYMENT.md` 第 3、4 步可能讓 `.env` 在 app 目錄留一份；README／使用手冊／政策第二節仍有短名「領導力羅盤」（建議統一「領導力羅盤八向評測」）；`user-manual.pdf` 可能早於改名 ⚠️。
- 架構整理：`'ai-competency'` 預設值散落約 25 處；`REPORT === 'compass'` 分派散在多個檔案；FAQ「目前內建六份評測」寫死。

## 5. 相依套件漏洞（20 個，其中 14 個 high）

- 後端與前端的「正式環境相依」（`--omit=dev`）掃描皆為 **0 個漏洞**。
- 20 個全部在開發／建置／測試工具（vite、vitest、tailwindcss、postcss、jsdom→undici 等），不在正式執行路徑；正式站只提供 `dist/` 靜態檔。
- 殘餘風險很低：VPS 上做完整 `npm ci` 並建置，建置工具鏈會在正式主機執行。建議：CI 建置後把 `dist/` 交給 VPS，或至少先試 `npm audit fix`（非破壞性修復）。**不要**用 `--force`。

## 6. 確認沒問題的項目（節錄）

- 路由授權：admin／coach 兩個 router 統一掛載角色檢查，班級相關操作都檢查所有權；目標、閱讀清單皆以 userId 綁定；`/groups/mine` 不外洩報到代碼與待加入名單。
- JWT／cookie（httpOnly、lax、production secure、≥32 字元密鑰、改密碼／角色／停用即撤銷）、密碼雜湊與重設流程、角色管理護欄（不能降自己、保留最後一位管理員）、SQL 全為參數化。
- 註冊同意由伺服器強制；政策版本前後端一致且有測試；政策對教練／管理員可見範圍與程式行為一致（羅盤例外已寫入）。
- 前端：無 `eval`／`innerHTML`；`dangerouslySetInnerHTML` 僅用於 QR 碼；`target=_blank` 皆有 rel；JWT 不存 localStorage；PWA 不快取 `/api`；對比度已達 AA；作答頁鍵盤與螢幕閱讀器支援完整；無孤立死碼；lazy 拆分合理。
